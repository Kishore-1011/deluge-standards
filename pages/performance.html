Engineering Manual — Section 6

Performance & Execution Efficiency Guidelines

Official corporate engineering standards governing script execution optimization, API call minimization, bulk batching, loop efficiency, and statement limit management in Zoho Deluge.

Governor Limit & Efficiency Rule

Every Deluge script must be written for focused computational efficiency. Developers must minimize API calls, eliminate duplicate queries, optimize loops, and exit early to prevent statement limit breaches.

6.1 API Call Minimization & Bulk Batching Standard

Rule

Reduce API calls by batching data modifications into a single bulk call outside iteration loops. Never execute API calls or database updates inside loops.

Why

Executing API calls inside loops adds massive network latency and exhausts daily system API rate quotas.

Example

Good Example
deluge 
list bulkUpdateList = List();

for each dealMap in dealList
{
    updateMap = Map();
    updateMap.put("id", dealMap.get("id"));
    updateMap.put("Pipeline_Status", "VERIFIED");
    bulkUpdateList.add(updateMap);
}

if(bulkUpdateList.size() > 0)
{
    crmAPIResponse = zoho.crm.updateBulkRecords("Deals", bulkUpdateList);
}
Bad Example
deluge 
for each dealMap in dealList
{
    updateMap = Map();
    updateMap.put("Pipeline_Status", "VERIFIED");
    zoho.crm.updateRecord("Deals", dealMap.get("id").toLong(), updateMap);
}

Checklist

  • API calls moved outside loops
  • Bulk updates (updateBulkRecords) used
  • In-memory data caching

6.2 Loop Optimization & Early Exit Control

Rule

Validate precondition guard clauses at the top of functions to abort early, and execute break; immediately upon finding target items in loops.

Why

Returning early and terminating search loops saves CPU statement execution limits and prevents unnecessary computation.

Example

Good Example
deluge 
if(dealMap.get("Stage") != "Closed Won")
{
    return Map();
}

for each lineItem in lineItems
{
    if(lineItem.get("Is_Primary") == true)
    {
        targetLineItem = lineItem;
        break;
    }
}
Bad Example
deluge 
for each lineItem in lineItems
{
    if(dealMap.get("Stage") == "Closed Won")
    {
        if(lineItem.get("Is_Primary") == true)
        {
            targetLineItem = lineItem;
        }
    }
}

Checklist

  • Top-level guard clauses
  • Break statement on match
  • Flattened conditional logic

6.3 Field Selection & Memory Control Standard

Rule

Request only necessary fields in database queries (using COQL or field parameters) rather than fetching entire record payloads.

Why

Fetching full record maps with 100+ unused fields wastes memory and increases HTTP payload processing time.

Example

Good Example
deluge 
coqlQuery = "SELECT Id, Deal_Name, Amount FROM Deals WHERE Stage = 'Closed Won'";
coqlResponse = zoho.crm.coql(coqlQuery);
Bad Example
deluge 
allDeals = zoho.crm.getRecords("Deals");

Checklist

  • COQL for field selection
  • Only required fields requested
  • Lightweight memory overhead
