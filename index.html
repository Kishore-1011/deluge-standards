Introduction & Engineering Governance

Official internal engineering standards establishing mandatory Deluge development rules across all Zoho implementations.

Mandatory Engineering Playbook

This document defines the official internal coding standards for our Zoho Development Team. Compliance is mandatory for all developers, technical leads, and external contractors.

1.1 Document Purpose & Scope Standard

Rule

Every Deluge script across all Zoho applications (CRM, Books, Creator, Desk, Inventory, etc.) must strictly adhere to these engineering standards. Unstandardized code will be rejected during code reviews.

Why

Standardization ensures consistent, maintainable, and readable code across all company projects. It enables any developer to quickly understand, modify, or debug existing Deluge scripts without onboarding friction.

Example

Good Example
deluge 
/* Author : Kishore Employee Code : ETC-029 */
map syncDealToInvoice(string dealIdStr) 
{
    responseMap = Map();
    return responseMap;
}
Bad Example
deluge 
// No author header, unstandardized logic
d = zoho.crm.getRecordById("Deals", id.toLong());
m = map();
m.put("customer_name", d.get("Deal_Name"));
info m;

Checklist

  • Standard mandatory header included
  • Clean function structure
  • Applies across all Zoho applications

1.2 Importance of Standards & Benefits

Rule

Prioritize code readability, maintainability, and explicit variable declarations over clever or condensed code tricks. All Deluge code must be structured so any team member can scan it in under two minutes.

Why

Code is read far more often than it is written. Following clear standards reduces bug resolution time, eliminates technical debt, and speeds up peer code reviews.

Example

Good Example
deluge 
string customerEmail = customerMap.get("email");
bool isEmailValid = validateEmailFormat(customerEmail);
if(!isEmailValid)
{
    info "Invalid customer email format : " + customerEmail;
}
Bad Example
deluge 
e = c.get("email");
if(e == null || e == "" || e.indexOf("@") < 0) { return false; }

Checklist

  • Self-documenting variable names
  • Explicit type declarations
  • Readable execution flow

Rule

These standards apply to 100% of internal developers, technical leads, and external contractors writing Zoho Deluge code. No script may be deployed to production without passing the Code Review Checklist.

Why

Universal compliance prevents sub-standard code from entering live environments, ensuring high system stability and seamless team collaboration.

Good Example
deluge 
/* Author : Kishore Employee Code : ETC-029 */

    return Map();

// Direct patch deployed to production without author header or review

Checklist

  • Mandatory author header included
  • Code review completed before deployment
  • Full compliance with engineering standards
